# D10 — стресс-диагностика записи — 05.11.2026

Поручение: [Grafnot_Redesign_Prompt.md](Grafnot_Redesign_Prompt.md), реестр D10 — «конкурентная запись, структурный риск; диагностика двух писателей с управляемым чередованием, удаления профиля и unload/flush; технологию менять по требованиям и измерениям».

Скрипт: `scripts/d10-stress.cjs` (Playwright + Chromium, Linux, сборка рабочего дерева 05.11.2026). В гейты не входит: зависит от таймингов, идёт ~6 минут.

## Инвариант

Правка либо есть в хранилище, либо вкладка, где её сделали, громко сообщает «⚠ Конфликт вкладок» или «⚠ НЕ сохранено». Правка, которой нет в хранилище при статусе «Сохранено», — тихая потеря.

## Результаты

| Сценарий | Прогонов | Результат |
|---|---|---|
| Две вкладки одного профиля печатают с независимыми случайными задержками 0–700 мс (задержка автосохранения 400 мс), затем 1,5 с ожидания | 40 | Тихих потерь **0**. Конфликт показан в 37; в 3 правки не пересеклись по времени и сохранились обе |
| Вкладка закрывается через 0–380 мс после последнего нажатия (до срабатывания автосохранения), `beforeunload` включён | 20 | Потерь **0**: запись при уходе успевает |
| Вкладка B удаляет профиль (реестр и стор), пока во вкладке A несохранённая правка | 10 | Стор не воскрешён ни разу; вкладка A каждый раз показывает конфликт |
| Хранилище заполнено до отказа, вставлено 4000 символов одним действием | 3 | «⚠ НЕ сохранено» через 433–435 мс; прежняя запись в хранилище побайтно цела; после освобождения места следующая правка записана, статус «Сохранено» |

Первый замер квоты печатал 4000 символов по одному, и первые символы успевали сохраниться до отказа — сравнение с исходной записью было неверным. Повторено вставкой одним действием (3 из 3 одинаково).

## Вывод

Модель «оптимистичная запись со сверкой базы» (`decideFlush`, `lastSeenRaw`) на этих сценариях ведёт себя по инварианту: при конкурентной записи выигравшая правка сохраняется, проигравшая не теряется молча, а помечается конфликтом и остаётся в памяти вкладки (можно скачать или перезаписать). Смена технологии хранения по этим измерениям не требуется.

Что это не доказывает:

- Слияния нет: при конфликте пользователь выбирает одну версию (долг из README). В 37 из 40 прогонов одна из правок требовала ручного решения.
- Проверен только Chromium. Порядок событий `storage`/`pagehide` в Firefox и Safari, выгрузка вкладки мобильной ОС и аварийное завершение браузера не проверялись.
- Квота — только Chromium, ~5 МБ на origin; поведение при eviction хранилища браузером не воспроизводилось.
