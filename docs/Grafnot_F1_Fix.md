# Grafnot — исправление F1: реестр профилей между вкладками

Дата: 27 октября 2026 года. Статус: F1 исправлен; F2–F9 остаются открытыми.

## Проблема и поведение после исправления

Ранее вкладка сохраняла весь реестр из своей устаревшей React-копии. Создание нового профиля удаляло из списка изменения другой вкладки; вход из старого списка возвращал уже удалённый профиль без его данных.

Теперь UI-операции создания, входа, переименования, удаления и ручного импорта выполняются через общую Web Locks-блокировку для ключа реестра. Внутри блокировки читается актуальный реестр, выполняется операция и проверяется результат записи. Удалённый ID не может вернуться через устаревшую операцию входа или переименования.

Списки профилей обновляются по storage-событиям. При удалении активного профиля в другой вкладке:

- без несохранённых правок открывается выбор профиля;
- при несохранённых правках остаётся снимок в памяти, доступный для скачивания;
- запись и принудительная перезапись удалённого профиля заблокированы;
- принятие внешнего состояния переводит к выбору оставшихся профилей.

После ожидания блокировки перед сменой сессии повторно сбрасываются накопленные правки предыдущего профиля, чтобы не потерять ввод за время ожидания.

## Красные тесты и результат

До реализации новые E2E дали 0/2:

1. F1 two tabs preserve both created profiles and saved data — first created profile lost from registry.
2. F1 stale tab cannot resurrect a deleted profile — deleted profile resurrected by stale registry write.

После реализации эти сценарии проходят. Добавлен третий: F1 deleted active profile retains unsaved data and blocks overwrite. Он проверяет содержимое скачанного снимка, отсутствие восстановления ключа данных и переход к выбору профилей.

Четыре unit-теста проверяют одновременное создание с одинаковым timestamp, отсутствие восстановления удалённого ID, отказ записи при нечитаемом реестре, явное разрешение первого создания и проверку результата записи.

P26b теперь ждёт завершения асинхронного удаления строки. Проверки отсутствия строки, стора, настроек и записи реестра сохранены.

## Граница исправления

Для изменения реестра через UI требуется Web Locks API в HTTPS/localhost. Если общей блокировки нет или её получение отклонено, операция отказывается от записи; небезопасного варианта без блокировки нет. Проверено в системном Chrome на localhost. Другие браузеры отдельно не проверялись.

Начальная синхронная загрузка/миграция реестра не перерабатывалась: F2 и остальные находки отчёта аудита требуют отдельных шагов. Восстановление уже потерянных до исправления записей профилей этим изменением не выполняется.

Commit/push не выполнялись. Preview остановлен, временная копия тестового скрипта удалена после проверки.
