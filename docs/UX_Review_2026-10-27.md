# Пользовательская проверка Grafnot — 27.10.2026

## Объём и метод

Ручной проход по рабочей production-сборке в браузере: тетради, редактор, контекстные вкладки, вычисления, задачи, неделя, карта, библиотека и конструкторы промптов, профили, внешний вид, корзина, горячие клавиши, экспорт и общий поиск. Проверены обычное окно компьютера около 1265×712 и узкий экран 390×844. Основной язык RU; дополнительно проверено переключение KZ → RU, светлая и тёмная темы.

Данные созданы через интерфейс на отдельном origin `http://127.0.0.1:5199`: профиль «Проверка UX», три заметки, две задачи, граф и пользовательские шаблоны. Исходники приложения в рамках этой проверки не изменялись. Чтение кода использовано для подтверждения причин отдельных дефектов. Скриншоты находятся в `docs/ux-review-2026-10-27/`.

Это проверка основных пользовательских сценариев и доступных элементов, а не исчерпывающая проверка всех сочетаний состояний. Безвозвратное удаление, очистка корзины и удаление профиля не выполнялись. Мобильная проверка выполнена изменением viewport; аппаратная клавиатура телефона, реальные касания и браузеры iOS/Android не проверены.

Приоритеты: **P1** — неожиданное изменение данных или повреждение полезного результата; **P2** — заметное препятствие работе; **P3** — ясность, оформление и удобство.

## Подтверждённые функциональные дефекты

### UX-01 · P1 · Поиск выполняет задачу вместо открытия

Шаги: общий поиск → ввести «презентацию» → выбрать найденную задачу «Подготовить презентацию до пятницы.».

Результат: переход в список и уведомление «Задача выполнена»; задача исчезает из активных и оказывается во «Выполненных». Отдельной команды завершения в строке результата нет. Ожидание: открыть или выделить задачу, сохранив её статус. После проверки статус восстановлен.

Причина подтверждена: `src/App.tsx:1129` вызывает `toggleTask(e.refId)` при выборе результата группы tasks.

Исправление: открывать карточку найденной задачи; завершение оставить явному чекбоксу. Проверка исправления: выбор активной и выполненной задачи не меняет done.

Доказательство: [07-search-completed-task.jpg](ux-review-2026-10-27/07-search-completed-task.jpg).

### UX-02 · P1 · Поле кода уничтожает переносы строк

Шаги: «Промпт-помощник» → Code review → язык Python → вставить:

```python
def greet(name):
    if name:
        return "Hello " + name
    return "Hello"
```

Результат в поле, предпросмотре и скопированном промпте:

```text
def greet(name):    if name:        return "Hello " + name    return "Hello"
```

Такой Python-код уже не соответствует исходнику. Проблема повторена на мобильном экране. Причина: `src/PromptWorkbench.tsx:229` выбирает textarea только при наличии переноса в default; у поля код default пустой (`src/data.ts:32`), поэтому используется однострочный input (`src/PromptWorkbench.tsx:253`). SQL-поле с default SELECT 1 построено тем же способом; отдельно многострочный SQL не проверялся.

Исправление: задавать тип поля явно либо разрешать многострочный ввод для свободного текста. Проверять точное сохранение переводов строк и отступов при вставке, копировании, сохранении и добавлении в заметку.

Доказательства: [04-mobile-code-field.jpg](ux-review-2026-10-27/04-mobile-code-field.jpg), повреждённый текст также виден в [02-note-layout.jpg](ux-review-2026-10-27/02-note-layout.jpg).

### UX-03 · P1 · Сохранённый шаблон изображения не восстанавливает теги и модель

Шаги: «Арт: персонаж» → добавить blue eyes и watercolor → усилить первый тег → выбрать Flux → «Сохранить как шаблон» → открыть созданную запись повторно.

Результат: в библиотеке остаются название `((blue eyes)), watercolor (Flux)` и текст `blue eyes and watercolor`, но рабочая область показывает Pony, пустые теги и 0 символов. Переход к другому шаблону и обратно не помогает. Сам текст в библиотеке не исчез: дефект именно в восстановлении состояния конструктора.

Причина: `src/App.tsx:1597` передаёт в PromptImageWb название, но не содержимое шаблона; `src/PromptImageWb.tsx:56` и `src/PromptImageWb.tsx:57` всегда создают Pony и пустой массив. Сохранение в `src/PromptImageWb.tsx:385` записывает только результат, defaults пустой; модель и структура тегов отдельно не передаются.

Связанное проявление: встроенный «Арт: персонаж» обещает в строке библиотеки masterpiece/best quality и поля волос/глаз, но открывает тот же пустой конструктор. Это одна группа дефектов загрузки шаблонов изображений.

Исправление: определить сохраняемую структуру модели/тегов/весов и восстановление, включая совместимость существующих записей. Проверить round trip для Pony/SDXL/Flux и встроенный пример.

Доказательство: [01-image-template-empty.jpg](ux-review-2026-10-27/01-image-template-empty.jpg).

### UX-04 · P2 · Можно сохранить незаполненный промпт как готовый

Создан текстовый шаблон «Краткий конспект» с обязательными {{тема}} и {{формат}}. При пустых полях «Сохранить» создаёт обычную запись с бейджем «Сохранённый» и текстом «Составь краткий конспект по теме . Формат:». При этом «Копировать» правильно блокирует действие и перечисляет недостающие поля.

Причина: Copy проверяет missingSlots (`src/PromptWorkbench.tsx:65`), Save сразу вызывает onSave (`src/PromptWorkbench.tsx:318`). Нужна одинаковая валидация либо явное сохранение черновика с отличимым статусом.

### UX-05 · P2 · Повторное уведомление о создании задачи

После выделения предложения в заметке и создания задачи появляются два уведомления «Задача добавлена», одно с действием открытия. Сама задача создана одна. Убрать дублирующее уведомление, сохранив полезный переход. Наблюдалось один раз в этом сценарии; отдельная проверка всех путей создания не проводилась.

### UX-06 · P2 · «Закрыть» у вычисления означает удаление

Визуально крестик и доступное имя «Закрыть» обещают закрытие, но обработчик удаляет вычисление из заметки. Подтверждено чтением `src/NotesView.tsx:989`, `src/NotesView.tsx:990`, `src/App.tsx:1025`. Вручную удаление не выполнялось. В этом обработчике нет отмены удаления. Переименовать действие в «Удалить вычисление» и обеспечить восстановление либо понятное подтверждение.

## Что прошло проверку

- Создание и редактирование заметок, повторное открытие, дублирование, перенос тестовой копии в корзину и восстановление.
- Создание отношения между заметками; нахождение похожей копии, открытие вкладок контекста «Связанное», «Похожее», «Задачи заметки», «Промпты», «Заготовки».
- Вычисление 2+3*4 = 14 с названием «Бюджет».
- Создание задачи из выделенного текста, дата «Завтра», описание, создание задачи через день недели, завершение и возвращение в активные.
- Создание и переименование графа, выбор состава, открытие карточки узла, масштабирование кнопкой «Вписать».
- Создание текстового шаблона, поиск/фильтры библиотеки, заполнение полей, копирование, сохранение версии, вставка результата в заметку.
- Поиск тегов, выбор blue eyes, свободный watercolor, усиление тега, переключение модели до сохранения.
- Переименование тестового профиля, переключение языка KZ → RU и темы; скачивание JSON; просмотр справки клавиш.

Успешные отдельные действия не означают отсутствия перечисленных выше дефектов в том же разделе.

## Очерёдность исправления

1. UX-01–03: прекратить неявное изменение статуса задач и порчу/невосстановление результата промптов.
2. UX-07–11: устранить переполнение, дать место редактору, вернуть заметный доступ к настройкам на телефоне, исправить контраст.
3. UX-04–06, UX-16–19: согласовать сохранение/удаление/обратную связь и довести восстановление данных и пустые состояния.
4. Остальные пункты: ясные подписи, структура библиотеки, подсказки и единое оформление.

В этой стадии исправления не вносились. Автоматические тесты повторно не запускались: добавлены только отчёт и скриншоты. Найденные сценарии требуют отдельных поведенческих проверок при исправлении; ранее пройденные unit/E2E не доказывают корректность этих UX-путей.
