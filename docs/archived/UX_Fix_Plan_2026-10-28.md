# План исправления дефектов UX-проверки 27.10.2026

Источник: `docs/UX_Review_2026-10-27.md` (UX-01…UX-29). Ссылки на код сверены 28.10.2026 — строки из отчёта актуальны.

## Правила выполнения

- Один шаг = один отчёт, затем стоп до команды.
- «Красный первым»: сначала e2e/unit на исправленное поведение, показать падение на текущем коде, затем исправление.
- Гейты каждого шага: `npm test`, `npx tsc -b`, `npm run e2e` (осознанно обновить `EXPECTED_CHECKS`), `npm run check:weight`, `oxlint` (0 errors), `npm run check:i18n`, `npm run check:contrast` (где затронуты цвета).
- Store только аддитивно (`SCHEMA_VERSION` + `migrate()`), конвейер сохранения не трогать. Новые строки — i18n ×3.
- Новые сценарии проверки = сценарии из отчёта (шаги воспроизведения переносятся в e2e почти дословно).

## Этап A · P1 — порча данных и результата

### F1 · UX-01 · Поиск открывает задачу, а не выполняет её
- Причина: `src/App.tsx:1129` — `toggleTask(e.refId)` в `pickPalette`.
- Изменение: убрать `toggleTask`; переходить на `#/plan/list/<taskId>`. `PlanList` принимает начальный `openId` → `setPanelId` (`src/PlanList.tsx:50`), подсветка/прокрутка строки; для выполненной задачи раскрыть группу «Выполненные».
- Тест: e2e — палитра → задача (активная и выполненная) → Enter: `done` не изменился, открыта панель этой задачи, тоста «Задача выполнена» нет. Deep link `#/plan/list/<id>` работает.

### F2 · UX-02 · Многострочные поля шаблонов
- Причина: `src/PromptWorkbench.tsx:229` — textarea только если default содержит `\n`; у `код` default пустой (`src/data.ts:32`) → `<input>` (`:253`) съедает переносы.
- Изменение: чистая функция `isBlockSlot(body, slot)` в `promptUtils.ts` — слот, стоящий на отдельной строке тела (`\n{{x}}` до `\n`/конца), или default с `\n` → textarea. Данные не меняются; `код` и `запрос` становятся многострочными. В textarea Enter = перенос строки, Ctrl+Enter = копировать (не ломать переход Enter → следующее поле для однострочных).
- Тесты: unit на `isBlockSlot`; e2e — вставка Python-кода из отчёта: точное совпадение (переносы и отступы) в поле, превью, буфере, сохранённой версии после повторного открытия и в заметке после «В заметку» (`appendPromptText`, `src/store.ts:510`). Отдельно SQL из нескольких строк. Мобильный вьюпорт 390.

### F3 · UX-03 · Шаблон изображения восстанавливает модель и теги
- Причина: `src/App.tsx:1597–1600` передаёт в `PromptImageWb` только имя; `src/PromptImageWb.tsx:56–57` всегда `Pony` и `[]`; сохранение `:385` пишет только итоговую строку, `defaults: {}`.
- Изменение:
  1. `LlmTpl` (`src/data.ts:11`): аддитивные необязательные `model?: AIModel`, `tokens?: string[]`; `SCHEMA_VERSION`+1, `migrate()` без потерь (старые записи остаются валидными).
  2. Сохранение пишет `model` и `tokens` (с весами) вместе с `body`.
  3. `PromptImageWb` получает `initModel`/`initTokens`; App вычисляет их: есть поля → из них; нет (старые записи) → разбор `body` по запятым с весами (обратная к `renderPrompt`, `src/promptUtils.ts:22`); встроенный «Арт: персонаж» → `fillBody(body, defaults)` → теги (masterpiece, best quality, long black hair, …).
  4. Сохранённые версии `PromptSave` kind image (уже имеют `model`/`tokens`) — проверить, что открываются так же.
- Ограничение: у старых Flux-записей веса уже потеряны при рендере — восстанавливаются только теги; указать в README.
- Тесты: unit — разбор ∘ рендер для Pony/SDXL/Flux, веса `((x))`/`(x:1.2)`; миграция старой записи. e2e — сценарий из отчёта (Flux, blue eyes усилен, watercolor) → сохранить → уйти → вернуться: модель Flux, 2 тега, вес сохранён, счётчик символов > 0; встроенный «Арт» открывается непустым.

## Этап B · P2 — компоновка, мобильный доступ, контраст

### F4 · UX-07 · Место для редактора на ноутбуке
- Причина: фиксированные 224 + 300 + 300 px (`src/index.css:69`, `:328`, `:88`).
- Изменение: `min-width` для редактора (~560 px); на ширине < ~1360 px контекстная панель становится оверлеем (drawer) поверх редактора, а не колонкой; rail по умолчанию свёрнут до 64 px при нехватке ширины (без перезаписи явного выбора пользователя в prefs).
- Тест: e2e 1265×712 — ширина редактора ≥ 560, заголовок не обрезан (`scrollWidth ≤ clientWidth`), формула видна целиком; 1440 — раскладка прежняя.

### F5 · UX-08 · Неделя не расширяет страницу
- Причина: `src/index.css:414` — 240 + 7×140 px без контейнера прокрутки.
- Изменение: обёртка сетки с `overflow-x: auto`, `min-width: 0` у предков; заголовок недели и «Входящие» остаются на месте.
- Тест: e2e 1265 — `document.documentElement.scrollWidth ≤ innerWidth`, сетка прокручивается внутри.

### F6 · UX-09 · Нет горизонтального скролла на телефоне
- Изменение: найти переполняющие элементы списка задач (поля composer, строки с длинным названием) — `min-width: 0`, `max-width: 100%`, перенос/многоточие для названий.
- Тест: общий e2e-проход всех разделов на 360/390/430 с длинным названием задачи и заметки: нет горизонтального скролла документа.

### F7 · UX-10 · Настройки на телефоне
- Изменение: иконка настроек в мобильном заголовке страницы (≥ 44 px, aria-имя ×3) + в пустом состоянии палитры команда «Настройки» в первых четырёх. Профили и корзина доступны со страницы настроек.
- Тест: e2e 390 — настройки за 1 касание с каждого раздела.

### F8 · UX-11 · Контраст главной кнопки в тёмной теме
- Причина: `src/index.css:74` — `#fff` отдельно от общего primary.
- Изменение: использовать токены primary-кнопки (цвет текста/фона с ≥ 4.5:1); добавить пару «кнопка Создать» в `scripts/check-contrast.cjs`.
- Тест: `npm run check:contrast` сначала красный на новой паре, затем зелёный; визуальная проверка обеих тем.

### F9 · UX-12 · Карта вписывается при открытии
- Изменение: автоматическое «Вписать» при первом открытии графа, смене графа и изменении размера, пока пользователь сам не двигал/масштабировал; минимальный размер подписи при вписывании; цель узла ≥ 44 px на touch.
- Тест: e2e — после открытия масштаб равен результату «Вписать»; после ручного зума ресайз не сбрасывает его.

## Этап C · P2 — сохранение, удаление, обратная связь

### F10 · UX-04 · Сохранение незаполненного промпта
- Причина: Copy проверяет `missingSlots` (`src/PromptWorkbench.tsx:65`), Save сразу вызывает `onSave` (`:319`).
- Изменение: Save использует ту же проверку, что Copy: подсветка, фокус на первом пустом обязательном поле, список недостающих.
- Тест: e2e — шаблон с пустыми обязательными полями: «Сохранить» не создаёт запись; после заполнения создаёт.

### F11 · UX-05 · Один тост при создании задачи
- Причина: два источника — `src/App.tsx:515` (`notify` в `addTask`) и `src/NotesView.tsx:582` (`notifyAction` с «Открыть»).
- Изменение: `addTask` принимает опцию тихого режима (или уведомление переносится к вызывающим); из заметки остаётся один тост с «Открыть».
- Тест: e2e — ровно один тост для каждого пути: выделение → задача, Ctrl+Alt+T, composer плана, ячейка недели.

### F12 · UX-06 · Удаление вычисления
- Причина: `src/NotesView.tsx:989–990` («Закрыть») → `deleteCalc` (`src/App.tsx:1024`) без отмены.
- Изменение: aria-имя/title «Удалить вычисление» (ключ ×3); `deleteCalc` с Undo-тостом, восстановление на прежнюю позицию.
- Тест: e2e — удалить → «Отменить» → вычисление с именем и выражением на месте.

### F13 · UX-17 · Кнопка создания
- Причина: «+ Новая заметка» открывает палитру (`src/App.tsx:1258`); двойной плюс.
- Изменение (рекомендация): подпись «Создать» и один значок; палитра открывается в режиме создания с вариантами Заметка / Задача / Промпт сверху (N1 по-прежнему создаёт заметку сразу в разделе Заметки). Альтернатива — прямое создание заметки. **Требует решения.**
- Тест: e2e — подпись/aria соответствует действию, первый вариант создаёт выбранный тип.

### F14 · UX-18, UX-19 · Пустые состояния карты и «Связанного»
- Изменение: пустой граф — EmptyState «Добавьте заметки в граф» с кнопкой, открывающей «Состав». Вкладка «Связанное»: три разных текста — нет связей у заметки / нет предложений / все заметки связаны; подпись счётчика «исходящие».
- Тест: e2e — новый граф показывает кнопку и она открывает состав; заметка без связей не показывает «Всё связано».

### F15 · UX-16 · Восстановление из JSON
- Код: `src/SettingsPage.tsx:281`.
- Изменение (рекомендация): «Восстановить из файла» → чтение JSON → проверка через существующие `migrate()`/`LoadResult` без изменения `store.ts` → предпросмотр (заметки/задачи/графы/промпты, версия схемы) → импорт **как новый профиль** (текущие данные не затрагиваются). Плюс текст о составе экспорта (текущий профиль, без настроек интерфейса — уточнить по `exportRaw`). Альтернатива — замена текущего профиля с автоматическим предварительным экспортом. **Требует решения.**
- Тест: unit — валидный/битый/будущая версия схемы; e2e — экспорт → импорт → новый профиль с теми же количествами; битый файл → ошибка, данные не изменены.
