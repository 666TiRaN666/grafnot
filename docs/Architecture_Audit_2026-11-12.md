### Компромиссы и удачные решения (не трогать)

- **`useMenu`** — ограниченная ответственность (1 опция, только поведение меню-кнопки по WAI-ARIA), 8 потребителей. Не расширять. Общая часть «закрыть по клику снаружи / Esc / вернуть фокус» нужна и попапам (A3) — её стоит вынести в отдельный маленький хук, а не добавлять в `useMenu` режимы.
- **Меню у каретки (`[[`, `/`)** в `NotesView` — паттерн combobox: фокус обязан оставаться в редакторе, клавиши перехватываются в фазе capture. Объединять с `useMenu` нельзя.
- **`ProfileMenu`** — своя фиксированная позиция поверх `useMenu` (иначе обрезается навигацией). Оправдано.
- **Пропсы App → раздел** — один уровень (NotesView: 23 пропса + объект из 20 действий). Context или store-менеджер не окупятся.
- **Алиасы токенов** `--text → --u-text` в `index.css:7-15` — слой совместимости, уже сведён.
- **`selectionModel.ts`, `useListState`/`listPrefs`, `trashRestore.ts`, `storage/profileBoot.ts`, testid-контракт, `npm run gates`** — образцы, по которым стоит делать остальное.
- **Пины карты в prefs, а не в сторе** — задокументированное удобство, не данные.
- **`PlanWeek` импортирует `TaskPanel` из `PlanList`** — один раздел, одна модель задачи (`store.tasks`), режимы не расходятся.
- **Плоская `src/`** с префиксами разделов — дело вкуса; перенос в папки разделов даст большой diff без изменения поведения. Не делать сейчас.
