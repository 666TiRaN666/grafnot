# Grafnot — исправление F2: ошибка чтения реестра при запуске

Дата: 27 октября 2026 года. Статус: F2 исправлен. F1 остаётся исправленным; F3–F9 на этом этапе отдельно не проверялись и не дорабатывались.

## Проблема

Исключение первого getItem('grafnot-profiles-v1') возвращало статус absent. Загрузка принимала временно недоступный реестр за первый запуск, создавала новый реестр и скрывала существующие профили. При наличии legacy-данных начиналась миграция, хотя состав профилей был неизвестен.

## Исправление

- [src/profiles.ts:89](D:\Opencode\HumanAComputer\grafnot-prototype/src/profiles.ts:89): добавлен статус unavailable. Только значение null означает отсутствие ключа. Пустая строка — corrupt с сохранением исходного raw.
- [src/profiles.ts:127](D:\Opencode\HumanAComputer\grafnot-prototype/src/profiles.ts:127): ошибка чтения больше не преобразуется в absent.
- [src/storage/profileBoot.ts:127](D:\Opencode\HumanAComputer\grafnot-prototype/src/storage/profileBoot.ts:127): при unavailable загрузка останавливается до создания профиля, восстановления реестра, записи журнала и копирования legacy-данных. Результат помечен registryFailed и registryReadFailed.
- [src/App.tsx:1348](D:\Opencode\HumanAComputer\grafnot-prototype/src/App.tsx:1348): отдельные заголовок и текст ошибки чтения на существующем блокирующем экране. Кнопка повтора перезагружает приложение и читает реестр заново.
- src/i18n.ts: два ключа в RU/EN/KZ. Создание через палитру и Quick Add блокируется существующим механизмом registryFailed.

Формат сохранённых данных, SCHEMA_VERSION и зависимости не менялись. Существующие незакоммиченные изменения не откатывались.

## Красные регрессии

Перед реализацией упали все четыре новых unit-теста:

1. distinguishes a registry read failure from an absent key — ожидался unavailable, получен absent.
2. treats an existing empty registry value as corrupt, not absent — ожидался corrupt, получен absent.
3. keeps the existing registry intact after a transient read failure and recovers on retry — исходный реестр p1/p2 заменён новым pf….
4. does not start legacy migration when the registry cannot be read — появились журнал, копия стора и новый реестр.

После реализации все четыре проходят. Проверяется сохранность исходного реестра, activeId, имён и ключей данных, отсутствие новых ключей при отказе и восстановление после нового запуска.

## Браузерные сценарии

Группа G32-registry-read содержит две проверки:

- Временный отказ первого чтения, отдельный проход на RU/EN/KZ. До повтора: блокировка, Quick Add недоступен, 0 записей реестра и сторов, журнал миграции отсутствует. Реестр и два стора совпадают с исходными строками. После повтора доступны оба исходных профиля и заметка второго профиля.
- Постоянный отказ чтения с несколькими перезагрузками: отдельно для существующих профилей и для legacy-данных без реестра. Данные не меняются, копии и журнал не создаются. После восстановления доступа существующие профили открываются, а настоящая первичная миграция legacy-данных выполняется штатно.

Сравнение набора ключей не зависит от порядка перечисления localStorage. Все браузерные данные изолированы от пользовательских профилей.
