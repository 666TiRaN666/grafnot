# Архитектура Grafnot

Короткая карта для того, кто меняет код. Подробности поведения — `README.md`, нормы UI — `AGENTS.md` (N1–N9), история решений — `docs/Architecture_Audit_2026-11-12.md`. Правила ниже проверяет `npm run check:arch` (входит в `npm run gates`).

## Слои

```
main.tsx → App.tsx (оболочка)
             ├─ разделы: NotesView, PlanList/PlanWeek, MapView, PromptLib + Prompt*/SkillBuilder, TrashPage, SettingsPage
             │     └─ вложенные части раздела: EditorToolbar, NoteContext, NoteAttach, PromptInsert, TaskPanel …
             ├─ ui/       общие механизмы интерфейса (без знания о заметках и задачах)
             ├─ модели    чистые функции домена (*.ts без React)
             └─ хранение  store.ts, profiles.ts, storage/profileBoot.ts, prefs.ts, listPrefs.ts, exportRaw.ts
```

- **`App.tsx`** — загрузка профиля, конвейер сохранения, связка действий (id, время, тосты, Undo, маршрут), каркас, палитра. Правил домена здесь нет: изменение стора — `setStore((s) => ops.<операция>(s, …))`.
- **Разделы** получают данные и действия пропсами из App (один уровень, без контекста и state-менеджера) и держат у себя только временное состояние интерфейса.
- **`ui/`** не импортирует модели домена и разделы.
- **Модели** (`storeOps`, `trashRestore`, `selectionModel`, `taskGroups`, `isoDate`, `calcModel`, `textMatch`, `paletteModel`, `promptLibrary`, `imageModel`, `skillModel` …) — чистые функции с unit-тестами. Логика, которую можно проверить без DOM, живёт здесь, а не в компоненте.
- **Хранение** — единственное место, где трогают `localStorage`. Схема и миграции (`store.ts`), профили и конвейер сохранения неприкосновенны (`AGENTS.md`).

## Кто владеет данными

| Что | Владелец | Где меняется |
|---|---|---|
| Заметки, задачи, графы, промпты, шаблоны, корзина | стор профиля (`grafnot-store-<id>`) | `storeOps.ts`, `trashRestore.ts`; вызывает App |
| Открытая заметка, раздел, открытая задача | маршрут (`ui/router.ts`) | `go()` / `navigate()`; `store.activeId` — только «куда вернуться при старте» |
| Настройки интерфейса (тема, язык, навигация, пины карты, плотность …) | prefs профиля (`grafnot-<name>:<id>`) | `prefs.ts`: `readPref` / `writePref` / `readPrefJSON` |
| Размер порций списков | `listPrefs.ts` | `useListState` |
| Выделение, открытые меню и попапы, черновики полей | компонент раздела | локальный `useState` |
| Тосты и отложенные действия (Undo) | `toastQueue.ts` | `notify` / `notifyAction` из App |

Одно значение — один владелец. Если раздел хочет показать то, что уже есть в маршруте или сторе, он вычисляет это, а не копирует в своё состояние. Исключение — охват карты: он пока хранится и в маршруте, и в состоянии (см. «Долги» в аудите).

## Общие механизмы: что брать вместо своей реализации

| Задача | Брать | Не делать |
|---|---|---|
| Меню у кнопки («⋯», «Вставить», переключатели) | `MenuButton` / `MenuPopup` (`widgets.tsx`) поверх `ui/useMenu.ts` | свои обработчики клика снаружи и Esc |
| Попап у якоря, не меню (поле поиска, форма) | `usePopover` (`ui/dismiss.ts`) + `useFitInViewport` | свой `pointerdown` на document, свой расчёт `innerWidth` |
| Удержать попап в экране | `ui/useFitInViewport.ts`; фиксированная панель внизу помечается `data-viewport-edge="bottom"` | `clampXY` в компоненте |
| Слой поверх страницы | токен `--u-z-*` (`ui/tokens.css`) | число z-index ≥ 10 |
| Клавиша страницы (`/`, `N`, стрелки, `T`) | обработчик в разделе + `pageShortcutAllowed(e)` (`ui/pageKeys.ts`) | своё условие «не в поле и не в модалке» |
| Поиск записей по тексту | `matchesQuery` и подсветка `<Hi>` (`textMatch.ts`) | `toLowerCase().includes(…)` |
| Выделение в списке или на карте | `selectionModel.ts` | свою логику Ctrl/Shift |
| Список с поиском, порциями и стрелками | `useListState` / `useListNav` | свой счётчик «показать ещё» |
| Удаление | сразу + `notifyAction(…, Undo)`; возврат — `reinsertAt` | диалог подтверждения (только корзина и профиль: `ConfirmDialog`) |
| Двухшаговое подтверждение в строке | `useArmConfirm` | свой флажок «нажми ещё раз» |
| Имя без повторов | `uniqueName` / `uniqueNoteTitle` / `uniqueGraphTitle` | цикл `while (taken.has…)` |
| Дата задачи, недели, файла | `isoDate.ts` (`toISODate`, `addDaysISO`, `fmtDue`) | `toISOString().slice(0, 10)` (это день по UTC) |
| Настройка интерфейса | `prefKeyFor` + `readPref` / `writePref` | `localStorage` в компоненте |

## События и клавиши

- Обработчик клавиш живёт в том разделе, к которому относится клавиша. Глобального диспетчера нет и не нужно.
- **Клавиша принадлежит слою, в котором фокус.** Открытый слой (меню, попап, диалог, список подсказок) обрабатывает свои клавиши сам; страничные клавиши проверяют `pageShortcutAllowed`. Решает фокус, а не то, что открыто на экране.
- **Esc закрывает верхний слой, и только его.** Закрывший слой вызывает `preventDefault()`. Обработчики разделов, которые сворачивают выделение или режимы, проверяют `e.defaultPrevented`. `bindDismiss` делает это для меню и попапов.
- Общие сочетания (Ctrl+K, Ctrl+Alt+N, Alt+0) — в `App.tsx`, работают везде. Реестр для экрана «Клавиши» — `shortcuts.ts`: новая клавиша записывается туда и в e2e-матрицу G28.
- Меню у каретки в редакторе (`[[`, `/`, меню выделения) — отдельный паттерн combobox: фокус остаётся в тексте, клавиши перехватываются в фазе capture. Их не переводят на `useMenu`.

## Когда создавать новую абстракцию

1. Сначала поищите готовое (таблица выше, `ui/`, модели). Похожее поведение почти всегда уже есть.
2. Общий механизм выносится, когда он **одинаков по смыслу** хотя бы в двух местах и меняется по одной причине. Совпадение кода ещё не повод.
3. Абстракция отвечает за одно: `useMenu` — поведение меню-кнопки, `bindDismiss` — закрытие, `useFitInViewport` — положение. Нужен режим или флаг ради одного вызова — значит, это другой механизм или код раздела.
4. Логика без DOM — чистая функция с тестом; хук — только тонкая обвязка вокруг неё (`toastQueue` → `useToasts`).
5. Исправляя повторяющийся баг, чините общий механизм и добавьте регрессионный тест на него. Обход в одном месте — не исправление.

## Как расширять

- **Новое меню.** `MenuButton items={…}` или `MenuPopup`. Esc, клик снаружи, фокус и стрелки уже работают.
- **Новый попап с полем.** Компонент с `usePopover(open, onClose, { trigger })`. Ref нужно отдать и в `useFitInViewport(open, ref)`. Позицию задают координаты якоря.
- **Новая операция над задачами.** Чистая функция в `storeOps.ts` с тестом, обёртка в App (тост, Undo), проп в раздел.
- **Новый инструмент редактора.** Расширение Tiptap в `editorExtensions.ts` (схема только расширяется, старые документы читаются), кнопка в `EditorToolbar.tsx`. Собственную модель документа поверх Tiptap не заводить.
- **Новая настройка интерфейса.** Имя в `PREF_KEYS`, чтение и запись через `readPref` / `writePref`.
- **Новый раздел.** Lazy-чанк в App, маршрут в `ui/router.ts`, клавиши через `pageShortcutAllowed`, поиск через `matchesQuery`.

## Проверки

`npm run gates` (быстрые) и `npm run gates -- --e2e` (полные). Семь правил `check:arch`:

| Правило | Что ловит |
|---|---|
| storage | `localStorage` / `sessionStorage` вне модулей хранения (App — только ключи стора и передача хранилища в слой хранения) |
| page-keys | рукописное условие «не в поле» вместо `ui/pageKeys.ts` |
| search | `toLowerCase().includes(` вместо `textMatch.ts` (исключения: автодополнение тегов, замороженный `store.ts`) |
| layers | `z-index` ≥ 10 вне шкалы `--u-z-*` |
| ui-boundary | импорт из `ui/` наружу (общие механизмы не знают о заметках, задачах и разделах) |
| dead-css | класс в CSS, который не использует ни один компонент (кроме классов, которые генерирует Tiptap) |
| dead-export | экспорт, который нигде не используется — ни в приложении, ни в тестах, ни в скриптах |

Исключение записывается в `scripts/check-arch.cjs` вместе с причиной. Самотест правил — `npm run check:arch:selftest`.
