# Grafnot — заметки, задачи и карта знаний

Веб-приложение: связный блокнот для учёбы.
React 19 + TypeScript (strict) + Vite + Tiptap + d3-force. Данные — только `localStorage`, офлайн-first, бэкенда нет.

## Запуск и проверки

```sh
npm install
npm run dev        # разработка
npm run build      # tsc + сборка в dist/
npm test           # unit-тесты (vitest)
npm run check:weight  # отчёт веса JS-бандла + предохранитель от baseline (лимитов нет)
npm run preview    # раздача собранного (для ручной проверки и e2e)
npm run e2e        # 259 e2e-проверок (Playwright, нужен preview :5199)
npm run e2e:matrix   # S5 + список задач под 12 фиксированными датами: сам собирает dist и поднимает свой preview :5199 (не в CI)
npm run check:i18n  # missing/parity/dead-гейт i18n-ключей (RU/EN/KZ)
npm run check:i18n:selftest  # мутационный самотест гейта (4 фикстуры)
npm run check:arch  # архитектурные правила (хранилище, страничные клавиши, поиск, слои, граница ui/, мёртвый CSS и экспорты) — ARCHITECTURE.md
npm run check:arch:selftest  # мутационный самотест правил (9 фикстур)
npm run gates      # все быстрые гейты одной командой (+ самотест раннеров): таблица итогов, подробности только по упавшим
npm run gates -- --e2e                     # + сборка, вес, свой preview :5199, полный e2e, аудит N1
npm run gates -- --groups=G20-plan,G21-week  # + сборка, вес, preview, только эти e2e-группы
```

E2E: 259 e2e-проверок на Playwright поверх `vite preview` (вход `e2e/check6.cjs`, обвязка `e2e/harness.cjs`, группы `e2e/groups/<имя>.cjs`; часть групп: `GROUPS=G20-plan,G21-week npm run e2e`)
(пустой старт, редактор, задачи, неделя, связи, вычисления, карта, переименование, панели, промпты, корзина/undo, мобильная навигация, тосты, профили,
блокировки битого стора, ErrorBoundary, честные статусы сохранения, две вкладки, восстановление реестра, адопция legacy).
Сьют не зависит от дня недели и часового пояса: даты сидов вида `@today+N`/`@mon+N` раскрываются внутри страницы (зона Asia/Almaty, T2); `npm run e2e:matrix` гоняет S5 и список задач по 12 датам (Пн…Вс, границы месяца/года).
Достоверность раннеров (D4): `gates` и `e2e:matrix` считают прогон зелёным, только если дочерний процесс завершился сам (не крах, не сигнал, не таймаут), напечатал итог `N/N passed` и это число совпадает с манифестом `e2e/manifest.cjs`; полный прогон явно сбрасывает `GROUPS`; проверка осиротевших сторов выполняется в конце полного прогона. Правила — `scripts/runner-lib.cjs`, самотест — `scripts/runner.selftest.cjs`.

Linux и Windows. Скрипты кроссплатформенные (только `node`, без shell-синтаксиса). Если один и тот же каталог открывается из обеих ОС (общий диск), `node_modules` должен нести нативные модули обеих (rolldown, lightningcss, oxlint): после `npm ci` выполнить `npm run deps:dual` — добавляет модули второй ОС тех же версий из `package-lock.json`, повторный запуск ничего не меняет. Браузер для e2e: `CHROME_PATH`, иначе системный Chrome/Chromium, иначе Chromium Playwright (`npx playwright-core install chromium`; на Linux без Chrome — так).

Пользовательский путь и гипотезы опыта собраны в [Journey Map Grafnot](JourneyMap.md).

Первый проход W7–W16: [сделано и отложено](docs/actual/First_Pass_Status.md).

Текущее поручение: [редизайн «Спокойное рабочее пространство»](docs/actual/Grafnot_Redesign_Prompt.md). ## CI (`.github/workflows/ci.yml`, P5')

- job `unit` (блокирующий): `npm ci`, `npm test`, `npx tsc -b`, `npx oxlint`, `check:i18n` + selftest, `check:arch` + selftest, самотест раннеров, `sync-readme --check`.
- job `e2e` (timeout 30 мин): build → preview :5199 → `npm run e2e` → `check:weight` (блокирующий, предохранитель +50% от baseline) → `check:contrast` и `audit-targets enforce` (временно неблокирующие: `continue-on-error`, числа зависят от шрифтов раннера; станут блокирующими после первого зелёного прогона на Actions) → upload-artifact с трассой при падении → остановка preview всегда.
- Реальный прогон Actions с dev-машины невозможен; YAML проверен локально теми же командами и распарсен (node-структурно + PyYAML).

## Возможности

- **Заметки** — список по времени изменения, поиск с AND-токенами, порции по 50, «показать ещё», клавиатура. «Новая заметка» создаёт её напрямую; палитра отдельно ищет по полному тексту, показывает по четыре результата и раскрывает остальные порциями по 50. Заметка из палитры открывается с кареткой у совпадения: первый блок со всеми словами запроса, иначе первое слово; без совпадения в тексте — в начале. Каретка, прокрутка и вкладка панели запоминаются на время сессии и восстанавливаются при возврате к заметке; временная панель возвращается только с Back/Forward (новое открытие из списка, палитры или навигации показывает её закрытой).
- **Редактор** — новая заметка с пустым заголовком и фокусом в тексте; вычисляемое имя по первой непустой строке (до 80 кодовых точек) или «Без названия» / «Untitled» / «Атаусыз», единое для всех разделов и `.md`-экспорта. Tiptap (B/I/H/списки, undo/redo), `[[`-ссылки, меню «Вставить» и `/`, заготовки. Ссылка `[[Имя]]` остаётся в тексте и подсвечена (`data-wikilink`), Ctrl/⌘+клик открывает заметку; переименование заметки переписывает `[[старое]]` в других заметках. Клик по заметке в списке ставит каретку в текст (на desktop). Число связей одно везде: список, кнопка «Все связи» и панель считают каждую связанную заметку один раз в обе стороны (`linkedNoteIds`). Меню «⋯» заметки: экспорт, копия, членство в графах («В графах», `notes-menu-graph`), удаление; под списком — ссылка в корзину со счётчиком. Компактный блок связей, задач и промптов (на телефоне — одна прокручиваемая строка, список связей в листе); контекст закрыт по умолчанию, три вкладки, закрепление только при остатке ≥560 px редактору. Вычисления появляются после добавления, удаляются с Undo. Промпт заполняется рядом с заметкой и вставляется в запомненную позицию с обычным Undo и необязательной привязкой. «Отмена»/Esc возвращают фокус в текст на прежнюю позицию; уход в другую заметку, раздел или профиль закрывает окно без записи и показывает тост «Копировать результат».
- **Задачи** — экран-Список: одна строка инструментов (переключатель «Список / Неделя» слева, поиск `/` справа), под ней строка быстрого добавления — первичное действие (подсказка «Введите название новой задачи…», метка «Название новой задачи», «Enter — добавить» при вводе; пустое название не создаёт задачу; `N`, Enter добавляет и оставляет фокус; чипы срока и описание раскрываются слоем поверх списка, не сдвигая его); группы по срокам + Выполненные со шевроном; строка: чекбокс (цель 36 px), текст и описание, справа источник «из: …» и срок по состоянию (просрочено — `--u-warn` с подписью, сегодня/завтра — акцент, прочее — нейтрально), меню `⋯` (общий `MenuButton`: Esc, клик снаружи, стрелки, возврат фокуса); открытая задача подсвечена `--u-sel` с полосой. Пустой список — подсказка на месте списка без второй кнопки «Добавить»; «Показать ещё» (`tasks-more`) считает только строки развёрнутых групп (свёрнутые «Выполненные» больше не дают ложного «Показать ещё 1», `pageTaskGroups`); панель задачи (адрес `#/plan/list/<id>`: поиск Ctrl+K открывает задачу, не отмечая её, раскрывает группу и подсвечивает строку), удаление сразу + Undo; выбранный срок сбрасывается после добавления задачи; создание из текста заметки с привязкой `noteId` и чипом «из: …», тост «Указать срок» открывает панель этой задачи.
- **Календарь** — неделя Пн–Вс: заголовок-диапазон («9–15 ноября 2026», `weekRangeLabel`), «‹ ›» с названиями (`week-prev/next`, ←/→) и «Сегодня» (`T`); сверху лоток «Без даты» (активные задачи без срока, приёмник drag), ниже семь колонок с шапкой (день, дата, число открытых задач); сегодня — дата в круге акцента и лёгкая тонировка колонки, выходные — нейтральная тонировка; попап добавления у ячейки, отдельный чекбокс, drag задач по дням с Undo. Пустая неделя сохраняет сетку, а строка состояния ведёт к ближайшей задаче (`week-next-task`). «Сегодня» (и `T`) всегда отвечает: возвращает к текущей неделе и коротко отмечает сегодняшний день (кольцо колонки и покачивание даты, Web Animations; повторное нажатие перезапускает, геометрия не меняется; при `prefers-reduced-motion` — только кольцо). На desktop при ширине области ≥980 px семь колонок, уже — container query перестраивает неделю в список дней (без горизонтальной прокрутки); на mobile видны все семь дней с отметкой числа задач (`day-count`) и повестка выбранного дня. Дни недели и месяц — на языке интерфейса, включая KZ (`dateNames.ts`).
- **Карта** — несколько именованных графов + обзор; живая физика d3-force без стенок: связи — пружины, заметки отталкиваются, перетаскиваемая заметка тянет соседей, после отпускания граф успокаивается (при `prefers-reduced-motion` — сразу, без анимации). Камера вписывает граф, `viewBox` повторяет пропорции холста. «Закрепить на карте» в карточке заметки: закреплённая заметка стоит на месте, когда тянут другие; отпущенная после перетаскивания заметка закрепляется там, где её оставили (prefs `grafnot-map-pins:<id>` по графу). Новый граф сразу предлагает ввести имя (`map-graph-name`). Связи выбранной или наведённой заметки выделены, стрелка у края узла; взаимная связь — одна дуга со стрелками на обоих концах. Подписи сокращены до 14 знаков, у выбранной/наведённой — полное имя поверх узлов; при сильном отдалении (<0.45) обычные подписи скрыты. Карточка заметки не закрывает свой узел: камера сдвигается от неё (`revealShift`). Меню «⋯»: «Закрепить все» и «Сбросить раскладку» (с Undo закреплений). Пан, зум к курсору (0.15–2.5), сироты и битые связи. Маршруты графа и выбранной заметки; «На карте» из заметки и возврат восстанавливают её выделение, прокрутку и контекст.
- **Промпт-помощник** — библиотека из трёх видов (фильтры «Текст», «Картинка», «Навыки»; «+ Новый шаблон ▾» — текстовый шаблон, промпт для картинки или навык). **Текстовые шаблоны** с `{{полями}}` (многострочные для блочных слотов, Ctrl+Enter — копировать), оценка токенов; встроенные: Code review, SQL explain, ENT plan, «Структурный промпт», «Улучшить промпт», «Классификация по примерам» (названия встроенных шаблонов следуют языку интерфейса — `builtinTemplates(lang)`, тексты промптов на языке оригинала). **Конструктор картинки** — не форма, а композиция: модели Pony / SDXL / Flux / Midjourney с подсказкой синтаксиса; теги раскладываются по дорожкам в порядке чтения моделью (качество → персонаж → внешность → одежда → поза → место → свет → стиль → кадр → другое; словарь, угадывание по окончанию, ручной перенос в меню чипа или перетаскиванием), Alt+стрелки или «← Раньше / Позже →» в меню чипа переставляют внутри дорожки; в меню чипа вес меняется пресетами и шагом ±0,1 (0,1–2, `tag-w-up/down/value`); негативный промпт с «Типовыми исключениями» (Flux — не поддерживается, Midjourney — `--no`); кадр 1:1…16:9 → размер SDXL-бакета или `--ar`; префикс качества Pony `score_9…` (у нового промпта включён); вес числом `(tag:1.2)` / `(tag:0.8)` только у Pony/SDXL, SDXL без общей обёртки; Flux получает фразу (`fluxSentence`: «A girl with blue eyes, wearing … Setting: … Lighting: …», теги качества и веса отбрасываются). На узком экране результат картинки прилипает к низу (не выше 34vh, прокрутка внутри), пока правятся теги. Всё это сохраняется в шаблоне под введённым именем (модель, теги, исключения, кадр, префикс, дорожки); правки встроенного шаблона помечены, а уход с несохранёнными правками предлагает «Сохранить как шаблон» в тосте. **Конструктор навыка** — одна структура (что делает, когда применять, шаги, правила, формат ответа, примеры) собирается живьём в `SKILL.md` (frontmatter name/description, проверка имени и длины описания), системный промпт или `AGENTS.md` (с «Когда применять»); язык заголовков файла выбирается отдельно от интерфейса (`skill-lang-*`); копировать, скачать файл, сохранить в библиотеку кнопкой или Ctrl+S (встроенные навыки — образцы, копия получает своё имя: `code-review-2`). Ctrl+S сохраняет и в конструкторе текстовых шаблонов. Словарь тегов — статический sample (версия и дата в UI), проценты помечены «пример данных». Заполненные шаблоны привязываются к заметкам, Ctrl+K находит сохранённые промпты.
- **Оболочка** — настройки отдельной страницей, меню профиля в навигации desktop и шапке mobile, пять мобильных вкладок. «+» подписан по разделу; режимы: по разделу, всегда заметка, выбор заметки/задачи. При уменьшении visualViewport с активным полем таббар скрывается. Статус сохранения виден на обеих ширинах, mobile-кнопка ведёт к существующим действиям восстановления или настройкам данных. Сохранены баннеры failed/conflict/blocked, экспорт из памяти и raw-восстановление. Запуск открывает последний профиль, если реестр прочитан и его `activeId` указывает на существующий профиль; иначе — выбор профиля (повреждённый или недоступный реестр по-прежнему даёт баннер). Язык — первой строкой настроек названиями «Русский / English / Қазақша» (`lang-RU/EN/KZ`); имя профиля по умолчанию («Основной» / Main / Негізгі) следует языку. Корзина: восстановление оставляет на странице корзины и предлагает «Открыть». Настройки → Данные: копии называются `grafnot-<профиль>[-saved]-ГГГГ-ММ-ДД.json`; «Скачать текущую версию» (из памяти, с ещё не записанными изменениями), «Скачать сохранённую копию» (из браузера) и «Восстановить из файла» — строгая проверка файла (типы, повторные id, будущая схема), запись в новый профиль (имя берётся из имени копии, язык — текущий), чтение назад и сверка отпечатка; при любой ошибке реестр и текущие данные не меняются. Нижние листы на телефоне закрываются свайпом за ручку; Back/Forward к заметке возвращает её временную панель (Navigation API; без него — по метке записи в `history.state`, Firefox/Safari).
- **Выделение (заметки и карта, `selectionModel.ts`)** — одна модель: Ctrl/⌘+клик добавляет и убирает, Shift+клик — диапазон в порядке списка (на карте, где порядка нет, — добавляет), Ctrl/⌘+A — всё в списке или на карте (только когда фокус в этом разделе, не в поле и не в тексте), Esc и «×» снимают. В списке заметок кнопка «Выбрать» (`notes-select`) включает режим с чекбоксами, в нём обычный клик отмечает, а не открывает; Ctrl/⌘+пробел и Shift+пробел — клавиатурные двойники. Панель `SelectionBar`: «Выбрано: N», «В граф ▾» (добавить или убрать), «В корзину» — одной операцией с одним Undo (`trashNotes`, `setMembers`). На карте: рамка — Shift/Ctrl+перетаскивание по пустому холсту или режим «Рамка» (`map-box`), обычное перетаскивание по пустому месту по-прежнему панорамирует, средняя кнопка панорамирует всегда, правая больше не панорамирует; перетаскивание выбранного узла двигает всю группу и закрепляет её; для двух и более узлов — «Закрепить», «Открепить», «В граф ▾», «Убрать из графа», «В корзину»; для одного — карточка заметки.
- **Редактор: отступы (`editorIndent.ts`)** — одна модель: Tab в абзаце или заголовке повышает уровень отступа блока (атрибут `indent` 0–8, `data-indent`), одинаково на пустой и заполненной строке и для всех абзацев выделения; символы не вставляются, поэтому повторные нажатия работают. В списке (маркированном, нумерованном, чек-листе) Tab вкладывает пункт, в блоке кода вставляет табуляцию, в таблице переходит по ячейкам (после последней — новая строка). Shift+Tab — обратно; если убирать нечего — прежний путь к заголовку; ведущие табуляции старых заметок снимаются им же. Esc выводит из текста (Tab дальше по интерфейсу, Enter — обратно). Всё — транзакции с Undo/Redo, сохраняется в документе.
- **Редактор: форматирование (`editorExtensions.ts`, `EditorToolbar.tsx`)** — панель над текстом (липкая на desktop; на телефоне видна во время правки и прокручивается в своей строке), одна позиция Tab, стрелки внутри (шаблон ARIA toolbar), кнопки не забирают выделение, `aria-pressed` с состоянием `mixed` для частично оформленного выделения. Группы: отмена/повтор · стиль абзаца (обычный, заголовки 1–3, цитата, код) · шрифт (без засечек/с засечками/моноширинный) и размер (4 ступени) · Ж/К/Ч/З · цвет текста (6 + авто) и выделение цветом (5 + нет) · «⋯» (надстрочный Ctrl+., подстрочный Ctrl+,, код в строке, очистить форматирование) · маркированный, нумерованный список, чек-лист · абзац (выравнивание ×4, межстрочный интервал, интервал между абзацами, отступ) · ссылка (адрес, проверка: только http/https/mailto, Ctrl/⌘+клик открывает) · таблица (строки и столбцы, строка заголовков, удаление) · найти и заменить (Ctrl+F/Ctrl+H из текста, счётчик, регистр, «Заменить все» одним Undo). Меню `/` и «Вставить»: нумерованный список, чек-лист, цитата, блок кода, разделитель, таблица. Вставка с форматированием — по умолчанию, без форматирования — Ctrl+Shift+V (ProseMirror). Имена узлов и меток совпадают с официальными пакетами Tiptap (`textStyle`, `highlight`, `textAlign`, `superscript`, `subscript`, `table…`), которые не установлены (правило «без новых зависимостей»). `@tiptap/extension-list` (TaskList/TaskItem) объявлен явно: тот же 3.31.3, что уже ставил StarterKit, новых пакетов в `node_modules` нет.
- **Совместимость заметок** — схема только расширена: старые документы читаются без изменений (`editorExtensions.test.ts` сверяет JSON старой и новой схем). Документ, который схема не может прочитать (файл из более новой версии), не открывается пустым и не перезаписывается: заметка показывается только для чтения с баннером и кнопкой «Скачать данные заметки» (`note-unsupported`).
- **Меню (`ui/useMenu.ts`)** — одна модель для всех выпадающих меню: «⋯» и «Вставить» заметки, меню промптов, «⋯» и переключатель графов на карте, меню чипа тега, «⋯» задачи, профиль. Закрытие кликом снаружи (фаза перехвата), Esc с возвратом фокуса на кнопку, уход фокуса по Tab, выбор обычного пункта; флажки в меню не закрывают его; стрелки, Home, End; `aria-expanded`.
- **Попапы (`ui/dismiss.ts`)** — закрытие одно на меню и якорные попапы (`bindDismiss`: клик снаружи в фазе перехвата, Esc, если его не использовал внутренний обработчик). `usePopover` — для попапов, которые не меню: попап дня недели, «В заметку ▾», редактор ссылки, «+ Связать» на карте. Кнопка-открыватель считается «внутри»; Esc, «Отмена» и выбор возвращают фокус на неё (редактор ссылки — в текст), клик снаружи оставляет фокус там, куда нажали. В экране попап держит `ui/useFitInViewport.ts` (позиция — у якоря, сдвиг на величину выхода за край, заново при смене размера экрана, например при открытии клавиатуры); нижняя граница — верх видимых панелей с `data-viewport-edge="bottom"` (панель вкладок на телефоне), так что попап не уходит под неё. Меню у каретки (`[[`, `/`, выделение) — отдельный паттерн: фокус остаётся в тексте.
- **Поиск (`textMatch.ts`)** — одно правило для списков заметок и задач, корзины, карты (поиск узла, связь, состав, переключатель графов), `[[`, «В заметку», вставки промпта, библиотеки и палитры: без учёта регистра, каждое слово запроса где угодно в названии или тексте, в любом порядке. Подсветка отмечает те же слова. Шаблоны ищутся по всему телу, а не по сниппету карточки. Автодополнение тегов в конструкторе изображений — не поиск записей и сохраняет свой префиксный отбор.
- **Страничные клавиши (`ui/pageKeys.ts`)** — одно правило допуска для `/`, `N`, стрелок и `T` недели, Ctrl/⌘+A карты: клавиша действует, только когда фокус не в поле или тексте и не внутри открытого слоя (меню, попап, диалог, список подсказок, модалка). Решает фокус, а не то, что открыто на экране: закреплённая панель или панель задачи страничные клавиши не выключают, фокус внутри них — выключает. Обработчики остаются в своих разделах; общие сочетания (Ctrl+K, Ctrl+Alt+N, Alt+0) работают везде, Ctrl+Alt+T — и из текста заметки.
- **Оболочка «Лист» (W5, уровни уточнены 2026-11)** — навигация на своей нейтральной поверхности `--u-side` с границей `--u-border`, контент на `--u-card`; «Новая заметка» — приподнятая кнопка, а не второй выбранный пункт; меню профиля содержит только профили (`menuitemradio`) и «Управление профилями», «Корзина» и «Настройки» в нём есть только на телефоне (там нет навигации); всплывающие слои — `--u-shadow-pop`; «Сохраняется…» нейтральное, красный только для ошибок. Навигация 224/64 px, иконки 18 px, поиск и статус сохранения в навигации на desktop; на mobile поиск и статус остаются в шапке. На странице по одному `palette-open` и `save-state`. Кнопка «Новая заметка» содержит один «+». Неделя прокручивается внутри своей области, не расширяя страницу.
- Навигация автоматически свёрнута при ширине <1200 px; явный выбор сохраняется в `grafnot-side-mode:<id>`. Старый `grafnot-side:<id>` не определяет режим. `Alt+0` возвращает автоматическую навигацию и закрывает контекст, `Ctrl+Alt+N` создаёт заметку (и из текста; AltGr печатает символ). Буквенные сочетания сверяются и по физической клавише — работают в русской и казахской раскладке. Во всех списках `/` — поиск (и в корзине), `N` — создать (в промптах открывает меню «Новый»), Esc выводит из поля поиска. Одинаковые тосты не складываются. Настройки → Клавиши: 30 строк реестра (`src/shortcuts.ts`, включая Tab/Esc в тексте и клавиши выделения), включая `[[`, Ctrl+клик по ссылке, Ctrl+S в конструкторах и Alt+←/→ для тегов; каждая проверяется в G28. Все `aria-label` переведены (RU/EN/KZ). Светлая/тёмная темы, RU/EN/KZ.

## Модель данных (`src/store.ts`)

```ts
Note  { id, title, content (Tiptap JSON), text, linkedIds: string[], calcs, updated }
Graph { id, title, noteIds: string[] }   // заметка может быть в 0..N графах
TaskItem { id, text, desc?, done, due?: ISO, noteId? }
PromptSave { id, kind: 'image'|'llm', title, model?, tokens?, templateId?, params?, noteId?, created }
LlmTpl { id, name, body, defaults, kind?: 'image', model?, tokens? }  // v6: состояние конструктора картинки
TrashMeta { incoming: string[], graphs: string[], at }  // v7: что указывало на удалённую заметку
Store { notes, tasks, trash, trashTasks, graphs, prompts, customTpls, activeId, trashMeta }  // + schemaVersion 7 при записи
```

Архитектурные решения (не менять молча):

1. **Связи — только по id, не по заголовкам.** Переименование O(1), висяков по построению нет: удаление заметки вычищает её id из чужих `linkedIds` и из `graph.noteIds`, а запись `trashMeta[id]` (v7, W4, D3) хранит, кто на неё ссылался и в каких графах она была; Undo и «Восстановить» возвращают связи и членство туда, где источник ещё существует, не откатывая других правок (`src/trashRestore.ts`). Непустые заданные заголовки уникальны (автосуффикс); пустые `title: ''` допустимы и не получают суффикса. Вычисляемые имена не записываются в стор.
2. **Нет поля «тетрадь».** Единственный источник принадлежности — `graph.noteIds`; «Без графа» вычисляется. Новые заметки стартуют без графа и назначаются через модалку состава.
3. **Миграции — чистая функция `migrate()` + `schemaVersion`.** Старые title-ссылки резолвятся в id за один проход, недостающие цели считаются и показываются тостом. Тесты: `src/store.test.ts`.
4. **Физика графа изолирована в `src/graphLayout.ts`** (единственное место, знающее про d3-force): `layoutGraph` — устоявшаяся раскладка ручными тиками с seeded-случайностью (карта открывается в покое, детерминированно для e2e); `liveGraph` — живая симуляция для перетаскивания и закреплений. Тесты: `src/graphLayout.test.ts`.
5. **Промпты живут в общем сторе**, а не в отдельном хранилище. Привязка односторонняя (`promptSave.noteId`), обратная сторона — вычисляемый фильтр. Словарь тегов — честно помеченный статический семпл (`promptData.ts`: версия, дата, источник), живого обновления нет по дизайну. Порог риска — именованная константа, синтаксис моделей — чисто презентационный `renderPrompt` (`promptUtils.ts` + тесты).
6. **Вес:** отчёт и предохранитель +50% от baseline, лимитов нет (`npm run check:weight`, baseline — `docs/weight-baseline.json`). Рост веса виден в отчёте.
7. **Показанная заметка — единственная цель команд (W2, D1).** Заметку на экране определяет маршрут `#/notes/:id`; текст, заголовок, удаление, копия, экспорт, связи и вычисления получают её id явно (`NotesActions`). `Store.activeId` — только последняя показанная заметка (посадка при запуске без хэша), он следует за маршрутом и командами не читается. Тесты: e2e `G33-identity`.
8. **Отложенные действия живут в своей сессии (W3, D2).** Действие тоста (Undo, «Открыть») запоминает профиль и эпоху сессии; любая замена стора целиком (смена/создание профиля, выход к выбору профиля, перечитывание из другой вкладки, разрешение конфликта — всё через `resetSession`) снимает такие тосты с сообщением «Отмена недоступна: данные профиля сменились», а запоздалый вызов не выполняется. Undo адресован сущности по id, а не «текущей».

## Профили (изоляция данных и настроек)

- **Реестр** — `grafnot-profiles-v1`: список профилей (`id`, имя, `created`) + `activeId` последнего активного.
- **Реестр в нескольких вкладках (F1):** создание, вход, переименование, удаление и ручной импорт выполняются через Web Locks с повторным чтением актуального реестра и проверкой записи. Список профилей обновляется по storage-событиям. Удалённый в другой вкладке профиль не восстанавливается старой записью; несохранённые правки остаются доступны для экспорта. Для изменения реестра нужен Web Locks API (HTTPS или localhost); без общей блокировки запись отклоняется.
- **Ключи профиля:** стор — `grafnot-store-<id>`; префы — `grafnot-theme|lang|side|side-mode|right|ctx|add-mode|hint-first:<id>`, `grafnot-list-limits:<id>`, `grafnot-tpl-limit:<id>`. `ctx` хранит закрепление контекста, `add-mode` — действие mobile «+»; `right` оставлен для legacy. Голые ключи — только legacy-путь до миграции.
- **Вход:** один профиль — автовход; несколько — экран `ProfilePicker` (вход, создание, переименование, удаление через arm-confirm). Меню профиля показывает до пяти профилей, управление и настройки; использует прежние проверки несохранённых данных. Дерево перемонтируется (`key={profileId}`), сессия сбрасывается. Автовход в последний из нескольких профилей отложен.
- **Миграция legacy:** первый запуск без реестра переносит `grafnot-store-v2` и голые префы в профиль «Основной» только после проверенной записи (read-back равен записанному); при нехватке места — блокирующий экран (скачать legacy / повторить / начать с пустого), реестр не создаётся, legacy цел, фантомных профилей нет. Нечитаемый legacy — блокировка до явного выбора; уцелевший остаток позже импортируется из пикера как отдельный профиль (тоже с проверкой записи).
- **Ошибка чтения реестра (F2):** исключение getItem — отдельный статус unavailable, а не первый запуск. До успешного чтения создание реестра, восстановление и legacy-миграция не запускаются. Блокирующий экран с повтором запуска сохраняет исходные профили и различает ошибки чтения и записи. Только отсутствующий ключ (null) считается первым запуском; пустая строка — повреждённые данные.
- **Сбой записи реестра при запуске:** миграция, создание первого профиля и восстановление повреждённого реестра блокируются до успешной записи и read-back реестра. Legacy-данные и голые настройки не удаляются до этой проверки. Служебный ключ `grafnot-adoption-pending-v1` хранит адрес назначения незавершённой миграции, чтобы повторные запуски не создавали копии профиля; после успешной миграции ключ удаляется.
- **Битый реестр** новым не затирается: бэкап `grafnot-profiles-v1:corrupt-<ts>`, восстановление из ключей `grafnot-store-*` (имена «Профиль N», тост), пустых default поверх данных нет.
- **Удаление профиля:** сначала реестр, потом данные (префы → стор последним); сбой удаления данных оставляет восстанавливаемую сироту (тост), а не призрачную запись.
- **Неизвестные поля данных:** поля верхнего уровня вне текущей схемы сохраняются вместе со снимком профиля при автосохранении, повторе записи, выходе из профиля и экспорте несохранённой версии. Принятие чужой версии заменяет также эти поля; перезапись своей сохраняет поля своей версии. В новом профиле набор пустой; метаданные между профилями не смешиваются.
- **Ошибка чтения профиля:** редактирование, создание и запись блокируются; экран «Хранилище недоступно» предлагает повторить чтение. При восстановлении доступа загружаются исходные данные. Ошибка чтения не считается пустым профилем и не создаёт фиктивную резервную копию.
- **Квота:** `saveStore` возвращает `false` — шапка показывает «⚠ НЕ сохранено», постоянный баннер (экспорт из памяти, повтор); смена/создание профиля блокируется до успеха или явного «Всё равно перейти».
- **Резервные копии и ручное восстановление:** нечитаемый стор копируется в `<ключ>:corrupt-<ts>` (не более 2 на ключ, дедуп по содержимому; если не влезла — отдельный тост + экспорт из памяти). Вручную: DevTools → Application → Local Storage → скопировать значение нужного ключа (`grafnot-store-<id>` или `:corrupt-*`) в файл; чтобы подсунуть его приложению — положить текст как значение ключа `grafnot-store-<id>` существующего/нового профиля и перезагрузить.

## Долги (осознанно не сделано)

- Архитектура (аудит 2026-11, `docs/Architecture_Audit_2026-11-12.md`): охват карты хранится и в маршруте, и в состоянии раздела; `App.tsx` ≈ 2000 строк — загрузка профилей и конвейер сохранения неприкосновенны и остаются там; меню у каретки (`[[`, `/`, выделение) держат последнюю копию `clampXY` (у них своя вертикальная логика); попап, которому не хватает места снизу, сдвигается вверх и может перекрыть свою кнопку (переворота над якорем нет); ссылка из панели контекста меняет `updated` заметки, а ссылка, протянутая на карте, — нет; формулы форматируют число по `ru-RU` при любом языке.
- 2026-11-12: из 10 полных прогонов e2e один раз упал G4-story «P7 rename propagation» (клик по пункту палитры по тайм-ауту, дальше каскад внутри истории); стор в диагностике корректен, G4 отдельно 2/2 зелёные — та же нестабильность истории, что в T2b ниже.
- Корзина без 30-дневной очистки (политика заявлена, enforcement нет).
- Нет истории версий заметок.
- Нет экспорта/импорта всей рабочей области одним файлом (только per-store raw и `.md`-экспорт заметок).
- Конфликт вкладок не мержится: три явных выбора (принять чужую / перезаписать моей / скачать мою), слияния нет.
- T2: сьют 5/5 зелёный (166/166), матрица будней 12/12; в CI не заведены `check:contrast` и audit enforce; остатков старого UI нет.
- T2b: P12 (G4-story) и клавиши редактора (G19-notes) — 0 падений из 30 изолированно и 0 из 10 в полном сьюте на 2026-10-18 (166/166 ×10); причина прошлых падений не устанавливается, запись нейтральная. 05.11.2026: причина P12 найдена — исходный масштаб читался, пока камера ещё вписывала новый граф; проверка ждёт стабильный `transform` (`docs/e2e-notes.md`).
